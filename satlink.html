1. Telemetry compression (NPCT)

Each message is compressed on its own, as a device sends it in one Iridium SBD burst. Dictionaries for common telemetry formats are built into the library, so both ends always have them. Damaged data is refused, never decoded wrong.

2. MAVLink drone link

A bridge on each side of the radio carries MAVLink between a ground station and a PX4 or ArduPilot vehicle: authenticated commands, an erasure-coded tunnel for parameters, missions and logs, and the flight controller's own link-loss failsafe in charge.

The limits, plainly

  • NPCT needs a Linux-class processor (about 1.2 MB of memory per call, about 0.5 ms per message on a desktop CPU): gateways and companion computers, not small microcontrollers.
  • Binary formats such as MAVLink and AIS carry already packed values: about 2x. Text and fixed-width telemetry: 4–11x.
  • Compression with integrity checking, and authenticated drone commands: not encryption.

Try it on your own data

The evaluation kit runs on Windows and Linux (x86-64, ARM64). One command, np_npct try <your log>, shows the bytes and Iridium credits per message next to zstd, with every message decoded back and checked. It includes the pre-compiled C99 binary library (zero source code exposed), a decoder for your provider's webhook, the drone link, and a step-by-step simulator test.
